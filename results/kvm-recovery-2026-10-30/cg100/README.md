# Two-clone cgroup divergence sample

Run on 2026-10-30 with QEMU 11.1.2 / Linux 7.2.11-arch1-1:

```sh
experiments/cgroup/run-probe.sh --out results/kvm-recovery-2026-10-30/cg100 \
  --count 2 --skip-guest-oom --divergence-percent 100
```

Each guest had 256 MiB configured RAM. "100%" means clone A dirtied the
probe's 32 MiB test region, not all guest RAM. Clone B stayed at its prior RAM
value; RAM and disk isolation passed.

| Measure | Before divergence | After divergence | Change |
| --- | ---: | ---: | ---: |
| Clone A QEMU PSS | 54,469 KiB | 87,282 KiB | +32,813 KiB |
| Clone B QEMU PSS | 54,049 KiB | 54,230 KiB | +181 KiB |
| A template-mapping private dirty | 2,508 KiB | 35,372 KiB | +32,864 KiB |
| B template-mapping private dirty | 2,504 KiB | 2,520 KiB | +16 KiB |
| cgroup `memory.current` | 310,681,600 bytes | 339,656,704 bytes | +28,975,104 bytes |
| cgroup `kernel` | 7,737,344 bytes | 7,778,304 bytes | +40,960 bytes |
| cgroup `sec_pagetables` | 409,600 bytes | 454,656 bytes | +45,056 bytes |

The cgroup charge increase differs from PSS/private-dirty changes because
cgroup memory includes file-cache charges and can vary with page-cache residency.
`sec_pagetables` includes KVM MMU allocations on this kernel, but cgroup
accounting is not a complete inventory of host RAM. These are single-run
measurements. Raw data is `result.json`; `summary.json` was generated by
`densevm stats`. Temporary guest artifacts were removed after collection.
