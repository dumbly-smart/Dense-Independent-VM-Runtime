# Twenty-target Alpine range

Run on 2026-10-26 with QEMU 11.1.2, Linux 7.2.11, KVM, and the plain
prepared Alpine ext4 guest. The probe launched 21 separate ordinary QEMU
baseline VMs and 21 template clones: 20 targets plus one attacker.

The host's persistent filesystem was nearly full, so this run's output
directory was on `/tmp`, a tmpfs backed by host RAM:

```sh
densevm probe --guest GUEST_DIRECTORY --count 21 --range \
  --out /tmp/RUN_DIRECTORY
densevm stats /tmp/RUN_DIRECTORY/result.json
```

This location changes storage accounting: `st_blocks` measurements below
describe files allocated in tmpfs, not persistent-disk allocation. It also
means the template file's resident pages consume host RAM and are represented
in the cache measurement.

## Results

- Configured guest RAM: 5,505,024 KiB (21 x 256 MiB).
- Aggregate process PSS before RAM divergence: 997,844 KiB for clones versus
  4,222,425 KiB for ordinary VMs, 76.4% lower in this single run.
- After clone A changed all of the 32 MiB test region, aggregate clone PSS was
  1,030,264 KiB; all other clones retained their expected RAM values.
- The conservative clone process-PSS-plus-full-template-cache estimate was
  1,258,932 KiB before divergence and 1,291,352 KiB after divergence. This
  accounting double-counts some mapped template pages. KVM metadata and host
  page tables remain `UNKNOWN`.
- RAM, disk, full-disk, guest identity, unique MAC, process, guest OOM, guest
  crash, reboot, and sibling-survival checks passed. Two pressure workers
  were OOM-killed; all guests remained responsive.
- Attacker-to-target connectivity passed before and after a target was
  killed. The localhost-only UDP probe delivered 64 of 64 packets with 0%
  reported loss.
- Base plus clone overlay allocation was 92,626,944 bytes after the probe's
  deliberate disk-isolation writes. Those allocations are in tmpfs and are
  not a persistent-storage benchmark.

The multicast QEMU socket network was bound to `127.0.0.1`, not an external
network. `result.json` is the raw probe output; `summary.json` is generated by
`densevm stats`. Process PSS is not total host RAM, and this is one sample, not
a benchmark distribution.
