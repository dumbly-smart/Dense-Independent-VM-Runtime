# Five-target Alpine range

Run on 2026-10-26 with QEMU 11.1.2, Linux 7.2.11, KVM, and the prepared
Alpine ext4 guest. The probe used six QEMU baseline VMs and six independent
template clones: five targets and one attacker. Its QEMU socket multicast
network was bound to `127.0.0.1` and did not attach to an external network.

Reproduce after preparing the plain (non-identity-validation) Alpine guest:

```sh
sh examples/alpine/prepare.sh ROOTFS_TAR SHA256 GUEST_DIRECTORY
densevm probe --guest GUEST_DIRECTORY --count 6 --range \
  --skip-guest-oom --out RUN_DIRECTORY
densevm stats RUN_DIRECTORY/result.json
```

## Results

- Five targets and one attacker were started as separate QEMU processes.
- Attacker-to-target connectivity passed before and after a target was killed.
- The UDP probe sent and received 64 of 64 packets (65,536 bytes), reporting
  0% loss for this localhost-only sample.
- RAM, disk, full-disk, guest identity, MAC, process, guest-crash, reboot, and
  sibling-survival checks passed.
- Aggregate clone process PSS was 277,441 KiB before the probe's 32 MiB RAM
  divergence and 310,279 KiB after it. Eight-target density was not tested.
- `densevm stats` reports 1,213,788 KiB baseline process PSS and
  572,423 KiB clone PSS plus the full resident template RAM file. KVM metadata
  and host page tables remain unaccounted for.

Guest OOM was **skipped**. An initial run with OOM enabled timed out waiting
for the Alpine guest's `PRESSURE-` response. The successful range run used
`--skip-guest-oom`, which preserves the range and other isolation probes but
does not establish OOM isolation for this prepared Alpine profile. That
failure remains a separate guest-probe issue to investigate.

`result.json` is the raw experiment output; `summary.json` is generated by
`densevm stats`. The UDP throughput value is a single local test and is not a
general network-performance result.
