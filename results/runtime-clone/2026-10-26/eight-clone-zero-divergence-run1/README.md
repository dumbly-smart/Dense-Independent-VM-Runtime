# Eight-clone comparison (zero guest RAM divergence)

Run on 2026-10-26 with QEMU 11.1.2, Linux 7.2.11, KVM, and 4 KiB pages:

```sh
densevm probe --out RUN_DIRECTORY --count 8 --divergence-percent 0
densevm stats RUN_DIRECTORY/result.json
```

`result.json` is the raw probe output. `summary.json` is generated by
`densevm stats`. The same generated guest artifacts were used for the
conventional baseline and the restored template clones. Each VM has 256 MiB
configured RAM, for 2 GiB total logical guest RAM.

## Measurements before intentional RAM divergence

| Measurement | Eight ordinary VMs | Eight template clones |
| --- | ---: | ---: |
| Aggregate process PSS | 1,625,501 KiB | 462,966 KiB |
| Aggregate process RSS | 1,816,412 KiB | 820,472 KiB |
| Clone PSS plus full template cache | — | 725,110 KiB |

Clone process PSS was about 71.5% lower in this run. The PSS-plus-full-cache
figure is a deliberately conservative accounting bound that double-counts
some mapped template pages; it was still below baseline process PSS here.
Neither figure includes KVM metadata or host page tables, and baseline PSS
does not include unmapped disk or kernel file cache. These measurements are
not a complete host-wide memory accounting result or a repeatable benchmark
distribution.

The full 256 MiB RAM template file was resident in the page cache. The report
uses sequential `/proc` samples while all eight clones are alive. It records
zero intentional divergence of the 32 MiB guest test region. Disk allocation
was measured after the probe's disk-isolation workload, not immediately
after clone creation, so it should not be interpreted as initial overlay
size. The raw file records guest identity/isolation checks and all measured
per-process details.
