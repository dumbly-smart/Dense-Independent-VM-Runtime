# Five-target Alpine range with guest OOM isolation

Run on 2026-10-26 with QEMU 11.1.2, Linux 7.2.11, KVM, and the plain
prepared Alpine ext4 guest. Six separate QEMU baseline VMs and six restored
clones were used: five targets and one attacker.

```sh
sh examples/alpine/prepare.sh ROOTFS_TAR SHA256 GUEST_DIRECTORY
densevm probe --guest GUEST_DIRECTORY --count 6 --range --out RUN_DIRECTORY
densevm stats RUN_DIRECTORY/result.json
```

The guest agent temporarily protected its coordinator from OOM selection and
raised the pressure workers' OOM scores. It restores the coordinator's prior
score after the pressure operation. This adjustment is limited to the
guest-side test command.

## Results

- Guest memory pressure requested 512 MiB across eight workers in a 256 MiB
  guest. Two workers were OOM-killed; the guest reported `oom_kill_delta=2`.
- All six guests remained responsive after pressure. The OOM isolation check
  passed.
- Five targets and the attacker had distinct identities and MAC addresses.
  RAM, disk, full-disk, process, reboot, crash, and sibling-survival checks
  passed.
- Attacker-to-target connectivity passed both before and after a target was
  killed. The localhost-only UDP probe delivered 64 of 64 packets with 0%
  reported loss.
- Guest OOM was enabled and verified in this run; unlike the prior
  [range run with OOM skipped](../alpine-five-target-range-run1/README.md),
  this report includes the OOM result.

The multicast QEMU socket network is bound to `127.0.0.1`; it is not attached
to an external network. `result.json` contains the raw experiment output and
`summary.json` is generated by `densevm stats`. PSS excludes KVM metadata and
host page tables, so it is not a complete host-wide RAM measurement. The UDP
throughput sample is not a general network-performance result.
